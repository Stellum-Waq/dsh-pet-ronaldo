## 1. 定义

本协议中，下列词语含义如下：

1.1 **「本插件」** 指 DSH 桌宠插件 **dsh-ronaldo-pet**（含其 Host 半、Client 半、配套技能 `dsh-pet-forge`），以及维护者 Stellum-Waq 与后续维护者。

1.2 **「桌宠包」**（Pet Package）指符合 [`SPRITESHEET-CONTRACT.md`](SPRITESHEET-CONTRACT.md) 与 `pet.json` 清单契约的一份自描述目录，包含图集（spritesheet）、音效与清单文件。

1.3 **「作者」** 指创作并发布桌宠包的自然人或组织，即本协议的授权方。

1.4 **「使用者」** 指通过本插件下载、安装、使用桌宠包的最终用户。

1.5 **「宠物社区 / 画廊」**（Gallery）指本插件内置的功能窗口及其背后的索引服务，用于收集、展示、下载、一键安装公开的桌宠包。

1.6 **「索引」**（Index）指画廊所使用的、描述桌宠包来源的元数据集合，包含两类来源：
   - **官方索引**：本插件仓库内 `gallery/index.json`，由作者提 Pull Request 加入；
   - **自动发现**：通过 GitHub 公开 API 检索带 `dsh-pet` 标签的公开仓库。

1.7 **「声明」**（Declaration）指作者在桌宠包 `pet.json` 中写入的 `sharing` 块（字段见附录 B），它是本协议**唯一**的机器可读接受方式。

1.8 **「撤回」**（Withdrawal）指作者按第 9 条终止本协议授权的行为。

## 2. 如何接受本协议

2.1 本协议**不适用「沉默即同意」**。作者只有在完成下列**全部**动作后，才被视为接受本协议：

1. 在桌宠包根目录的 `pet.json` 中写入 `sharing` 块，且：
   - `"protocol": "DPSL-1.0"`；
   - `"shared": true`；
   - `"statement"` 字段非空（作者的原创性/分发权声明，默认文本见附录 A）。
2. 把桌宠包发布到一个**公开可读**的 GitHub 仓库（第 6 条）；
3. 给该仓库打上 `dsh-pet` 标签（topic）。

2.2 本插件在生成宠物时会主动询问「是否愿意共享到宠物社区」，并提供「愿意 / 暂不共享 / 稍后再说」三个选项。**默认不共享**：
未明确选择「愿意」时，插件不会写入 `sharing` 块，也不会对任何仓库做收录动作。

2.3 插件在收录一个仓库时，以该仓库 `pet.json` 中**当前**的 `sharing` 块为准。此前的任何口头、对话或界面上的勾选，都不构成对后续修改的豁免。

## 6. 发布要求（技术性前置条件）

要被画廊**一键安装**（而不仅仅是被收录），桌宠包需满足：

6.1 仓库**公开可读**，默认分支可匿名访问。

6.2 仓库根目录（或唯一子目录）存在 `pet.json`，且通过本插件的严格校验：图集尺寸严格等于 `列数×格宽 × 行数×格高`、`states` 行号在范围内、`idle` 存在（见 `host.js` 的 `validateManifest`）。

6.3 `pet.json` 含合法的 `sharing` 块（第 2.1 条），其中 `sharing.repo` 指向本仓库自身。

6.4 建议但非必需：仓库根目录放置 `DSH-PET-LICENSE.md`（本协议副本）、`preview.png`（预览图）、`README.md`（说明动作与素材来源）。

6.5 仓库打了 `dsh-pet` 标签 —— 这是自动发现的唯一依据。

6.6 不满足 6.2/6.3 的仓库仍然可以被画廊**收录并展示**（提供仓库链接与下载通道），但画廊会明确标注「未采用 DPSL 协议 · 仅收录」，且不提供一键安装。

## 9. 撤回、下架与终止

9.1 **作者如何撤回**（任选其一，立即生效）：
- **a.** 把 `pet.json` 中 `sharing.shared` 改为 `false`；
- **b.** 删除整个 `sharing` 块；
- **c.** 从仓库移除 `dsh-pet` 标签；
- **d.** 把仓库转为私有或删除仓库；
- **e.** 在插件仓库提出 Issue（标题含 `[withdraw]`），或在原作者仓库/issue 中提出。

9.2 本插件方在**每次**抓取索引时重新校验上述条件，条件不满足即不再收录。

9.3 **时限承诺**：对于通过官方索引收录的条目，本插件方在收到明确撤回请求后 **7 日内**完成移除；
对于自动发现（`dsh-pet` 标签）的条目，因条件移除即刻生效，本地缓存最长 **24 小时**后失效。

9.4 **已下载的副本**：撤回**不影响**使用者此前已下载到本机的副本，也无法远程召回。
这是点对点下载与本地安装的固有性质，本插件方**不具备**也未承诺远程删除能力。
若作者希望更强控制，可选择不共享、只提供仓库链接，或只发布不含素材的「安装脚本」。

9.5 **本协议终止**后，第 3.2 条中针对**已分发副本**的授权继续有效（否则会凭空制造侵权）；
第 5 条义务在本插件方停止服务前持续有效；第 8、11、13 条在终止后继续有效。

10.1 **插件不上传你的文件。** 桌宠包由作者自己 push 到自己的 GitHub 仓库；插件只做**读取**。

- 下载的桌宠包（`storages/dsh-pet-forge/community/<owner>-<repo>/`）；
- 你选择共享时生成的「分享包」文件。

10.3 插件访问网络的目标**仅限**：`api.github.com`（检索标签）、`codeload.github.com` / `github.com`（下载归档）、以及官方索引地址。可通过配置关闭联网（见 `GALLERY-CONTRACT.md`）。

## 附录 B：`sharing` 字段表

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `protocol` | string | ✅ | — | 必须是 `"DPSL-1.0"`，否则画廊视为未采用本协议 |
| `shared` | boolean | ✅ | `false` | 是否同意收录。`false` 等同撤回 |
| `author` | string | ✅ | — | 展示用的作者署名（昵称即可，不要写不想公开的真名） |
| `repo` | string | ✅ | — | 仓库地址（`https://github.com/<owner>/<repo>`），应与实际仓库一致 |
| `license` | string | ⭕ | `DPSL-1.0` | 素材许可标识；如另有附加条款可写 `DPSL-1.0+CC-BY-NC` |
| `preview` | string | ⭕ | 自动探测 | 预览图相对路径（png/jpg/webp），建议 ≤ 512KB |
| `tags` | string[] | ⭕ | `[]` | 画廊筛选用标签，建议 1～6 个 |
| `contact` | string | ⭕ | `repo` 的 issues | 联系方式（Issue 链接或邮箱） |
| `allowRemix` | boolean | ⭕ | `true` | 是否允许他人二创并公开分享（第 3.4 条） |
| `allowCommercial` | boolean | ⭕ | `false` | 是否允许商业使用。**画廊不会替你开启它** |
| `attribution` | string | ⭕ | `author` | 附加到署名后的字符串（如带链接的 Markdown） |
| `submittedAt` | string | ⭕ | 抓取时间 | ISO 8601 时间戳 |
| `statement` | string | ✅ | — | 原创性/分发权声明；为空则不予收录 |
| `rights` | string | ⭕ | — | 素材权利说明（如：某素材不在授权范围内、同人来源、AI 生成方式）。**建议填写**，画廊会在详情里展示 |
| `extra` | object | ⭕ | — | 作者自定义扩展，画廊原样透传、不解释 |

**硬性规则**（由插件强制，见 `GALLERY-CONTRACT.md`）：
1. `protocol` + `shared: true` + 非空 `statement` 三者齐备，才视为「已授权」；
2. `shared: false` 或缺少 `sharing` → 只能以「仅收录」形态出现，且不提供一键安装；
3. 任何字段被用来伪造他人署名（`author` 与仓库属主明显不符且无说明）→ 人工审核后移除。

## 附录 C：常见问题的直白回答

**Q：我要不要先在本地把所有东西做完再共享？**
建议是。共享是**可选**的加分项：插件在你生成完宠物后会问一次，你说「暂不共享」也不会影响任何本地功能。

**Q：协议会不会限制我在自己的仓库里用 MIT？**
不会。代码用 MIT、素材用 DPSL 是很常见的组合；DPSL 只管「收录与分发」这件事。

**Q：我的桌宠是别人角色，能共享吗？**
技术上能，风险由你承担（第 8.2 条）。同人作品被权利人要求下架时，插件方会移除索引。更稳的做法是把 `sharing.author` 写成二创作者，并在 README 里注明原作与权利人。

**Q：我改了主意，只想留着自己用。**
把 `shared` 改成 `false` 就行（第 9.1.a）。已经被下载的副本收不回来（第 9.4），这点必须说清楚。

**Q：插件会不会悄悄把我的宠物传到 GitHub？**
不会。插件没有你的 GitHub 凭据，也不会替你 push。要让别人下载，必须**你自己**把仓库推上去并打 `dsh-pet` 标签（第 10.1 条、第 6.5 条）。

**Q：一键安装的时候，插件会执行仓库里的脚本吗？**
不会。插件只读取图集与 `pet.json`，按清单契约注册；不执行仓库中的任何脚本、不安装依赖。见 `GALLERY-CONTRACT.md`「安全边界」。

## 附：本协议的定位（给自己人看的一段）

DPSL **不是** OSI 认可的开源许可证，也不是软件许可。它是为「桌宠素材」这种**小型创作资产 + 集中式索引**场景写的一份**收录与分发授权**，
特点是：

1. **一件事只授权一件事**：授权范围窄到「让画廊能收录和分发」，而不是泛泛的「开源」；
2. **默认保守**：默认不共享、默认不商用、默认可撤回、默认不做 AI 训练；
3. **机器可读**：接受方式是 `pet.json` 里的结构化声明，而不是点击一个勾选框；
4. **撤回可验证**：撤回动作就是删一个字段，插件每次抓取都重新校验，不依赖人工流程；
5. **诚实**：做不到的事（远程召回已下载的副本）直接写在正文里，而不是含糊过去。
