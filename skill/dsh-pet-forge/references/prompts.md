# 生图提示词工程

生图提示词决定了两件事：**抠底能不能干净**、**动作像不像**。
本技能的提示词在 `scripts/lib/imagegen.mjs` 里按固定模板拼装，下面是每条要求的理由。

---

## 一、角色主图（Tier A/B 的第一步）

`buildCharacterPrompt(subject, opts)` 生成的提示词包含 6 组要求，**每一条都是为了下游能自动处理**：

| 要求 | 为什么必须有 |
| --- | --- |
| 「一个单独的 XX，全身正面全身像，居中构图」 | 画面里有多个角色时无法判断抠哪个；只画半身会导致落格后比例怪 |
| 「可爱 chibi / 卡通吉祥物风格，粗描边，扁平上色，简洁干净」 | **粗描边 + 扁平上色**是抠底质量的关键：抗锯齿边缘越少，`alpha` 就切得越干净 |
| 「**背景必须是纯白色 #FFFFFF**，没有任何渐变、阴影、地面、道具、边框或网格线」 | 抠底走的是**连通域泛洪**，需要边框是同一色。渐变/阴影会让边框颜色离散度飙升，`removeBackground` 会判定"背景不纯"直接放弃抠底 |
| 「角色四周留出充足空白，轮廓清晰，四肢不重叠」 | 落格时会按 alpha 裁剪再等比缩放；四肢重叠会让包围盒失真、比例变形 |
| 「不要任何文字、字母、数字、水印、签名、logo」 | 文字会被当成角色的一部分保留下来，且在缩放后糊成一团——看起来就像乱码 |
| 「画面里只能有一个角色，不要多视图、不要分格、不要参考线」「输出正方形构图」 | 模型很爱画"角色三视图"；一旦分格，抠底会把整个格子抠下来 |

> 用户给的 `--brief` 直接拼进第一句。所以 brief 要写**"是什么"**，不要写"画什么风格"
> （风格由 `--style` 控制，写重了会互相打架）。

## 二、常见 brief 写法

| 好 | 差 | 原因 |
| --- | --- | --- |
| `赛博朋克风格的机械猫，霓虹蓝与青色配色，大眼睛，圆润可爱` | `画一只猫` | 太泛，模型会加场景 |
| `一只戴红围巾的柴犬` | `柴犬，背景是雪地，很有氛围` | 会画背景 → 抠不掉 |
| `像素风史莱姆，绿色，扁平` | `史莱姆（8-bit，带像素网格）` | "像素网格"会被画成参考线 |

## 三、动作条带（Tier B）

`buildStripPrompt(subject, actionDesc, n, opts)` 要求：

- **同一个角色**、**颜色大小比例朝向完全一致** —— 否则切片出来的帧会"一顿一变"
- **从左到右等距排成一排**、**N 帧之间用空白隔开** —— 切片用 `sliceStrip`，优先按 alpha 空隙切
- **纯白背景、无分格线** —— 分格线会被切进图里

`ACTION_PROMPTS` 里给了 8 个动作的中文描述。写自定义动作描述时注意：

- 描述**姿态推进**而不是**结果**：写「双腿交替迈步，身体前倾」而不是「正在跑」
- 别写「4 张图」之外的排版要求 —— 排版已经由模板统一规定

### Tier B 的自动降级

`sliceStrip` 切完会做一次"是否靠边"的检查：如果超过一半的帧贴着格子边缘
（说明模型排版不准，帧宽不一致），就**丢弃这批条带、保留程序化版本**，并在
`warnings` 里说明。所以 Tier B 失败不会产出坏素材，只会退回 Tier A 的质量。

## 四、生成失败的排查顺序

1. **`未配置生图 API Key`** → 跑 dsh-eye 的 `setup.ps1`，或设 `DASHEYE_GEN_API_KEY`
2. **`绘图 API 4xx`** → 换 `--gen-size 1024x1024`（免费模型部分尺寸不支持）、确认模型名
3. **`生成的图片格式无法识别`** → 端点返回了非图片内容（错误页），检查 base-url
4. **`背景不纯，已跳过抠底`** → 见下表
5. **`抠底后画面几乎为空`** → 容差把角色也抠了

### 背景问题的处理矩阵

| 症状 | 参数 | 说明 |
| --- | --- | --- |
| 边框颜色离散度大（渐变背景） | 重新生图，brief 里强调纯白 | 最省事 |
| 背景是纯色但不是白色 | `--bg-tolerance 40`（默认）通常就行 | 泛洪会自动取边框色 |
| 背景纯白，但**角色内部的白眼白/白肚皮被抠掉了** | 不用管 | 泛洪是连通域算法，内部白色不连到边框，安全 |
| 角色本身接近背景色（白猫 + 白底） | `--bg-tolerance 20` 调小 | 容差太大会把角色边缘吃掉 |
| 背景是复杂场景 | 用 `--bg-mode none` 保留原图，或换图 | 没有 ML 分割，别硬抠 |

## 五、调色板提取

`--palette` 不传时，3D 路线会从 2D 主图自动提取 5 个主色（`extractPalette`），
按出现频次排序喂给 Blender。注意提取结果**包含背景残留的白色**，
所以 `buildScript` 里 `PAL[0]`（身体）经常是白色——这是符合预期的：
模型身体确实以浅色为主。想让 3D 更鲜艳，可以显式传：

```powershell
node ...\forge.mjs blender-plan --pkg <目录> --palette "#00f5f3,#0b0a23,#ffffff,#1e283c,#5aa8e8"
```
